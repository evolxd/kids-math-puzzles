# 思维闯关 · 产品架构设计

基于认知科学的自适应学习系统架构 · 2026-07-27

## 一句话论点

现在的"世界"式导航（六大板块，每块Lv1-5）是一份**内容目录**，不是一个**学习引擎**。目录解决的是"这个网站里有什么"，引擎解决的是"这个孩子现在最该做哪一题"。好的教育产品架构需要在目录之下，长出一层看不见的自适应逻辑——这份文档设计的就是这一层。

出发点很明确：不是要把"思维闯关"改造成一个冷冰冰的自适应测评系统。趣味性（探险地图、故事化包装）留在表层不变；这份架构解决的是表层之下的东西——内容怎么组织、怎么判断掌握了没有、下一题该推荐什么。

## 现状 vs 目标架构

| 维度 | 现状 | 目标架构 |
|---|---|---|
| 内容组织单位 | 6-7个固定"世界"（主题分类） | 世界保留作为探索入口；底层新增"技能"标签作为真正的学习/推荐单位 |
| 练习顺序 | 阻塞式——做完一个世界的所有题才自然换下一个 | 阻塞式用于**首次学习**（保留现状）；交织式用于**巩固复习**（新增"今日挑战"） |
| 难度决定因素 | 静态年级分档（三四/五六/七年级+） | 年级分档决定"能看到哪些内容"；**技能掌握度**决定"接下来该推荐哪一题" |
| 复习机制 | 无——做完就是做完，不会再被系统提起 | 同技能族的**新题**会在掌握度处于"半生不熟"区间时被优先推荐（不是重复同一题的答案） |
| 星星的含义 | 装饰性（正确题目计数） | 每个技能的**掌握度**指示（生疏 / 半熟 / 精通三档），有真实计算依据 |
| 反馈方式 | 家长事后批改（家长中心） | 保留人工批改（免费产品，不引入AI判分成本）；增加"自评"作为做完当下的第一层反馈 |

## 1. 核心概念：把"技能"作为新的学习原子单位

现有内容已经有两层分类，这次不动它们，只是新增第三层：

- **年级分档**（已有）：这道题适合哪个年龄段——三四年级 / 五六年级 / 七年级+
- **世界分类**（已有）：这道题的"风味"是什么，用于兴趣驱动的探索式浏览——称重推理、组合计数……
- **技能标签**（新增）：这道题真正在练的底层能力是什么，用于自适应推荐和复习

一道题 = 1个年级档 + 1个世界 + 1~3个技能标签。三层互不冲突，技能标签是加装的元数据，不需要重新组织现有页面结构。

**举例说明为什么需要第三层**——"称重与信息推理"这一个世界内部，其实混着好几种完全不同的能力：

| 题目 | 表面都是"称球" | 实际技能 |
|---|---|---|
| 8/9个球2次称出、12枚硬币3次称出 | ✓ | **分组排除法**——把物体分成几堆，用天平结果逐步缩小范围 |
| 1/3/9砝码、10桶药丸、通项公式 | ✓ | **数值编码**——用数字的组合/进位方式一次性编码出答案 |
| 3个球/12枚硬币"不知轻重" | ✓ | **双重不确定性推理**——同时要判断"是谁"和"偏轻偏重"两件事 |
| 2个鸡蛋100层楼 | ✗（完全不是称球） | **最优搜索策略**——如何设计一个"代价递减"的搜索序列 |

孩子做完整个"称重世界"，感觉是"练完了称重"，但其实这4种能力的巩固程度可能天差地别——有的孩子分组排除法一学就会，双重不确定性推理却总卡壳。不拆到技能这一层，系统没法知道该在哪里帮他多补一把。

## 2. 掌握度模型：为什么不用贝叶斯知识追踪

专业自适应学习产品（Khan Academy Mastery、ALEKS）用的是 Bayesian Knowledge Tracing 或 IRT（项目反应理论）这类统计模型——用概率估计"这个学生掌握某技能的可能性"，但这类模型需要大量数据校准参数，对一个个人维护的免费静态站来说是过度设计，也不透明（家长看不懂"掌握概率0.73"是什么意思）。

**推荐做法**：一个基于连续正确次数、且显式编码了"间隔"要求的启发式规则，逻辑简单、家长一眼能懂：

- **Lv.0 未接触**：这个技能下一道题都没做过
- **Lv.1 初步接触**：做过至少1道，但还没连续答对
- **Lv.2 半熟**：最近2道同技能题目，不用提示、不看答案，独立答对
- **Lv.3 精通**：最近3道同技能题目独立答对，**且分布在至少2个不同的自然日**

最后一条"至少2个不同自然日"是关键——直接把"间隔"这个原则写进"精通"的定义里，防止孩子一口气刷完3道就被判定为精通（那只是短期流畅度，不是长期掌握，参见 Bjork 的 "desirable difficulties" 理论 [[1]](#参考文献)）。

## 3. 自适应推荐："此刻最该做哪一题"

不是"做最难的"，也不是"做最简单的"，而是找**半生不熟**的那些——认知心理学里这叫"proximal region of learning"（Metcalfe & Kornell 提出，是维果茨基"最近发展区"在自主学习场景下的具体化 [[2]](#参考文献)）：完全不会的东西选择去学习它的性价比很低，已经精通的东西继续练收益也很低，真正值得投入的是"卡在中间"的那些。

具体规则：

1. 在孩子已经**接触过**的技能里（Lv.1或Lv.2，排除Lv.0和Lv.3），找掌握度最低的一个
2. 从这个技能对应的题目里，挑一道**还没做过**的
3. 如果所有接触过的技能都到Lv.3（都精通了），退回去推荐一个全新技能（Lv.0）里最基础的一题，扩大孩子的"技能前沿"

## 4. 交织练习："今日挑战"

现有的"世界"导航是纯阻塞式练习——做完称重世界所有题才会自然碰到组合计数。研究证据很扎实：Rohrer & Taylor 2010年的研究让四年级学生练数学题，交织练习组一天后测验正确率77%，阻塞练习组只有38%（效应量 d=1.21，几乎是双倍差距）[[3]](#参考文献)；2020年一项覆盖787名学生、54个班级的大规模课堂随机对照实验也重复验证了这个效应（d=0.83）[[4]](#参考文献)。

反直觉的地方在于：交织练习在**做题当下**的正确率反而更低（研究里是60% vs 89%），孩子会感觉"更难、更乱"——但这正是"desirable difficulty"（合意难度）：当下的吃力换来的是一天后记忆保留率的巨大提升。

**具体设计**：新增一个"今日挑战"入口（探险地图路径最上方一个特殊节点，每天刷新），固定挑5-6题，规则：

- 优先从 Lv.1/Lv.2（半生不熟）技能里各挑1题，题目来自不同世界（强制交织，不能连续两题都是称重）
- 搭配1道 Lv.3 技能的"热身题"（已经精通的，找回信心）
| 搭配1道 Lv.0 技能的"尝鲜题"（全新技能，保持新鲜感）
- 用当天日期做随机种子，保证同一天打开看到的题目一致，第二天自动换一批

这个入口同时是"交织练习"和"轻量间隔重复"的载体——不需要专门再造一套间隔重复算法。

## 5. 为什么经典的"间隔重复"不能照搬

Anki/记忆卡片式的间隔重复（SM-2算法：答对后间隔翻倍，答错重置）是为**离散事实**设计的——单词、公式、日期，这些东西"重新出现同一张卡片"是合理的，因为要巩固的就是"看到刺激能不能想起答案"这个反射。

但"思维闯关"里几乎每一题都是**独特的推理题**，不是可重复触发的事实卡片——如果100天后重新出现"12枚硬币称3次"这道题，孩子大概率记得的是"答案是分成4/4/4"这个结论本身，而不是重新推导一遍分组排除的思路。原样重复题目在这里几乎没有巩固价值，甚至可能造成"我看着面熟就是懂了"的虚假流畅感（fluency illusion，也是 Bjork 理论里明确警告的陷阱 [[1]](#参考文献)）。

**结论**：间隔重复原则要保留（隔一段时间回到同一个技能），但载体必须是**同技能族的新题**，不是同一题。这直接决定了第7节的内容库存要求。

## 6. 这套架构怎么长在探险地图UI上

- 路径节点从"一个世界一个节点"，升级成"世界节点 + 世界内部按技能分组的小节"（点进一个世界，题目按技能标签分组展示，不再是纯粹按题号顺序罗列）
- 星星从"正确题数"升级成"技能掌握度"的可视化——比如每个技能一颗星，颜色对应 Lv.1/2/3（灰/半亮/金）
- 路径最上方新增"今日挑战"特殊节点（第4节），视觉上可以做成会发光/每天重置的样式，和其余"世界"节点区分开
- 家长中心新增一个"技能地图"视图，横向对比每个技能的掌握度，比现在的"按天/周/月"时间视图更能回答"孩子哪里薄弱"这个问题

## 7. 数据模型变更

在现有 `localStorage` 结构基础上新增，不破坏现有 `solved`/`dates`/`grades`：

```
thinking.<tier>.attempts.v1
{
  "<questionId>": [
    { "date": "2026-07-27", "correct": true, "usedHint": false, "revealed": false }
  ]
}
```

技能掌握度不需要单独持久化——每次要用时，从 `attempts` + 题目的技能标签元数据现算（数据量小，100多道题，现算完全够快）。

题目的技能标签本身作为**新的元数据**加在 `HELP` 对象旁边（比如 `SKILLS = {"m1-01": ["group-elimination"], ...}`），不是运行时数据，是内容作者手工打的标签——这部分工作量是本架构里唯一需要"重新过一遍现有题库"的地方。

## 8. 分阶段实施路线图

| 阶段 | 内容 | 工作量 | 风险 |
|---|---|---|---|
| **Phase 1** | 给现有166道题打技能标签（`SKILLS` 元数据），先不接任何UI | 中——166道题要过一遍，但纯数据工作，零界面风险 | 低 |
| **Phase 2** | 掌握度计算（第2、3节的规则）+ 家长中心"技能地图"视图 | 小——复用现有 `grades`/`dates` 数据，加一段计算逻辑 | 低 |
| **Phase 3** | "今日挑战"交织练习入口（第4节） | 中——新UI入口+选题逻辑，但不改动现有页面 | 中 |
| **Phase 4** | 探险地图路径按技能分组展示、星星换成掌握度可视化（第6节） | 大——改动现有已上线的路径UI | 中，建议等Phase1-3验证过再做 |

和这次的年级拆分、探险地图试点一样的节奏：先做Phase 1这种低风险的地基工作，验证"技能标签这套分类是否真的好用、是否需要调整"，再逐步往上加。
